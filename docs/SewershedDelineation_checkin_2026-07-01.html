IoU = intersection-over-union: overlap area of generated vs. truth polygon divided by their combined area. 1.0 = perfect, 0 = no overlap.

2What I figured out

morph_close wins clearly, and it's robust. The morphological close (buffer the parcel union outward by r, fill every interior hole, buffer back in by r — the automated version of your manual select→buffer→fill→shrink workflow) tops the table. Every combo from selection-radius 50–150 ft × close-radius 50–150 ft lands in 0.78–0.795, so the method isn't fragile to the exact distances. Only selection-radius 200 ft degrades it (starts swallowing neighbors).

  • The census-block methods lost — and that's a real finding, not a bug. Blocks tile the landscape, which was the appeal, but the study area's blocks are much bigger than the actual served area, so blocks_dissolve and hybrid overshoot the truth. Testing it empirically (rather than assuming blocks would help) is worth a line in the writeup. Blocks still matter later for the demographic apportionment (Hill & Larsen 2023) — that's a different job.
  • Decoupling the two radii without breaking QC. Split selection_radius_ft (how far from a pipe a parcel counts as served — now sweepable) from pipe_buffer_distance_ft (kept as the thin QC ribbon). The low_population_match flag measures coverage against that thin ribbon, so widening selection no longer makes the flag silently read "fully covered." Regression-checked.
  • Fail-loud join, and it held. The sweep pairs truth SiteID == point AssetID_tx (the points layer has no FACILITYID) and asserts ~24 matches before scoring — a bad join would otherwise yield a silent all-garbage table. It matched all 24 cleanly.
  • One latent bug caught & fixed. The validation overlay cached geometries by a param2 key that pandas turns from None→NaN for the block methods (NaN = "not a number," pandas' null for numeric columns). A block-method winner would have written an empty overlay. Can't trigger today (morph_close wins with a real number), but hardened with a pd.isna check and unit-tested.
  • Basemaps via contextily, feet preserved. Rather than reproject the whole plot to Web Mercator (which would break the ft-based scale bars/arrows), I hand contextily the data CRS (EPSG:2264) and it warps the tiles to match — same look, data stays in feet. Satellite default; degrades gracefully (warns, still renders) when offline or contextily's missing.

3Decisions in play

Logged today in decision_log.md (2026-07-01):

  • Boundary = empirically-chosen method from a 4-way sweep; morph_close is the locked primary, IoU decides among the rest.
  • Fill ALL holes, keep ALL parts — solid polygon (interior lakes/ROW carry no population; filling avoids skewing the demographic join), multipart preserved (detached served pockets are real).
  • IoU floor = the success metric — median ≥ T1 and ≥ N/25 sites ≥ 0.5, with T1/N set after seeing the table (this snapshot). The sweep is a hard stop for human input, not an auto-pick.
  • Census blocks are a candidate (source: statewide NC TIGER 2020, filtered to the study area COUNTYFP20='063') — tested and beaten, per above.
  • QC → GeoPackage (multi-layer, network + delineation flags), satellite basemap default, build-custom verdict (no portable Python tool does this).
