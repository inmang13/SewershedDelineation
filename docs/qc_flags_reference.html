QC Flag Reference

SewershedDelineation — geometry-first QA on the shared network graph. Counts from the full run of 2026-07-02 (38,359 pipes, 1,066 flags).
How to read severity. The design is geometry-first: the digitized line direction is the authoritative flow direction; attribute fields (FROMMH/TOMH, inverts, slope) are cross-checks only. So a flag is review_required only when it can silently produce a wrong sewershed. Everything else is a warning — data hygiene for the GIS maintainer, safe to batch-review or defer.
review_required
Can corrupt a traced catchment. Look at each one — currently 45 total (44 unconnected snap gaps + 1 directed cycle). Each mapped type gets a PDF page.
warning
Attribute cleanup or informational. The tool already handles these correctly; fix in the source layer when convenient (1,021 total).

Network flags (src/network_qa.py — per pipe or manhole)

snap_gap — unconnected tier review_required — 44 flags

Trigger
Two graph nodes ≤ 20 ft apart that share no pipe and survived the 10 ft end-node repair as separate nodes (includes end↔junction pairs, which the repair never merges — 7 of these sit inside the 10 ft radius).
Means
The pipes genuinely do not connect in the traced network. A trace through this area stops short and drops the upstream catchment.
Action
Highest-value fix list. Check each in GIS: if the pipes physically connect, snap the endpoints in the source layer; if it's a real dead end (e.g. abandoned stub), no action.

directed_cycle review_required — 1 flag

Trigger
A small directed loop (≤ 10 nodes). Gravity flow can't circulate, so one or two pipes are digitized backwards.
Means
Any trace through the loop can walk the wrong way. the study area has exactly one: pipes 08373 / 08374 (no sample site touches it).
Action
Flip the backwards pipe's digitized direction in the source layer.

large_cycle review_required — 0 flags (none since geometry-first)

Trigger
A big strongly-connected tangle (> 10 nodes) — systematic direction errors stitching the tree into a loop.
Means
Was an attribute-era problem (one 270-node tangle); geometry-first direction eliminated it. If it ever reappears, large_cycle_suspects.csv lists member pipes with invert/slope suspects sorted to the top.
Action
Work the suspects CSV top-down; no map page (a citywide loop map shows nothing useful).

snap_gap — repaired tier warning — 13 flags

Trigger
Pipe end nodes 1–10 ft apart, auto-connected by the graph's pass-2 end-node repair.
Means
Tracing works — the tool bridges the gap. But the source geometry is offset and any other software reading the layer will see a break.
Action
Snap the endpoints in the source layer when convenient. Not urgent for this tool's results.

missing_direction warning — 112 flags · no PDF page

Trigger
FROMMH or TOMH is null.
Means
Direction is inferred from geometry (start point = upstream) — the pipe is marked QA_STATUS = direction_inferrable and traces correctly. You do not need to review these. Purely an attribute-completeness note for the maintainer.
Action
Maintainer can backfill FROMMH/TOMH from the manhole layer at leisure.

invert_conflict warning — 267 flags

Trigger
Recorded invert elevations imply uphill flow relative to the digitized direction (upstream invert lower than downstream; inverts ≤ 0 are treated as no-data and skipped).
Means
Either the invert fields are wrong (usual case — some imply nonsensical ~200 ft climbs) or, rarely, the geometry is flipped. Geometry wins; the trace is unaffected.
Action
Maintainer: check the invert data entry. Only escalate if a cluster of these coincides with a suspected direction problem.

attribute_slope_error warning — 2 flags

Trigger
SLOPE field is negative (pipes already flagged invert_conflict are skipped — same underlying question).
Means
Attribute inconsistency; geometry direction is used regardless.
Action
Fix the SLOPE value in the source layer.

disconnected_component warning — 105 flags

Trigger
A pipe fragment of ≤ 50 nodes (config disconnected_component_max_nodes) with no connection to any larger part of the network.
Means
Orphaned stubs or digitizing islands. Large separate components are NOT flagged — the network is genuinely many drainage basins (the largest holds only ~27% of nodes), and separate basins are normal.
Action
Only matters if a sample site lands on one (the pre-flight check check_sample_sites.py catches that — currently none do). Otherwise maintainer hygiene.

isolated_manhole warning — 522 flags

Trigger
A manhole whose FACILITYID appears in no pipe's FROMMH/TOMH. Two sub-cases in the description: snaps to a pipe endpoint within 5 ft (= ID mismatch between layers) vs. genuinely far from any pipe.
Means
Attribute bookkeeping. The trace snaps sample points by coordinate, not ID, so these don't affect results.
Action
Maintainer: reconcile manhole IDs with pipe attributes. Low priority.

Delineation flags (src/polygon_output.py — per traced sewershed)

no_upstream_found review_required

Trigger
The trace returns zero upstream pipes — the target is a headwater (or snapped to the wrong node).
Means
No sewershed polygon is produced. Either the site really is at the top of its line, or the manhole didn't resolve onto the network correctly.
Action
Verify the site location and its snap distance; confirm headwater status on the map before accepting.

large_catchment warning

Trigger
Sewershed exceeds 500 acres (config large_catchment_threshold_acres).
Means
Often legitimate (e.g. site 17506 → 832 ac). Just a prompt to eyeball the polygon.
Action
Sanity-check the boundary against the network extent.

low_population_match warning

Trigger
Less than 50% of the thin pipe-buffer ribbon overlaps any served parcel (config low_population_match_min_buffer_coverage; threshold is untuned).
Means
Pipes running through unparcelled ground — undeveloped/industrial land, a parcel-coverage gap, or a CRS mismatch. Scale-invariant, so small catchments don't false-flag.
Action
Check whether the trace area is genuinely low-parcel; if legitimate catchments keep firing it, lower the threshold in config.
